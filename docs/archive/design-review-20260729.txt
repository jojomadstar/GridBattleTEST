## 更新記錄（2026-07-29 第八輪：拳師普攻改為順移突進）

### 機制

普攻改成**順移到敵人正對格再出拳**。因為準心是「玩家前方第四格」（欄位鏡像），
順移到跟敵人同欄同列就一定打得到 —— 實測 256 組位置組合**全部命中、全部到位**。

演出：起點揚塵 → 路徑速度線 + 三道殘影 → 落點衝擊圈，角色用 easeOut 從起點滑過去。
邏輯位置立刻更新（命中判定才不會有時序問題），只有畫面在插值。

**例外**（都有測試涵蓋）：

- 百裂崩拳引導定身期間**不能順移**，會就地出拳
- 敵人瞬身到我方場地時沒有「正對格」可站，這時不順移

**落地僵直 0.22 秒**：沒有這個的話，拳師等於「保證命中 ＋ 走位完全自由」——
可以把所有移動都拿去閃招卻照樣每拳都中。有了僵直，順移到亮著的罡氣格上就真的躲不掉。

### 數值：你的擔心剛好相反

你說「攻速變慢怕很難抽牌」，但**順移讓命中率從『要手動對位』變成 100%**，
所以實際上是反過來 —— 集氣不再被揮空稀釋。實測用最初的 0.75s / 集氣 44：

| 職業 | 抽牌間隔 | 勝率 |
|---|---|---|
| 唐門 | 2.45s | 51% |
| 劍客 | 2.08s | 40% |
| **拳師（0.75s／44）** | **1.75s** | **92%** |

拳師變成抽最快、又贏最多。原因是它的招式（百裂崩拳約 160、亢龍有悔約 184）
本來是照「定位很難」去配的，現在定位免費了。

掃過 0.75 / 0.85 / 0.95 / 1.05 四組後定案：

```
攻速 1.0s（其他職業 0.34s）｜ 集氣 45（原本 34）｜ 普攻傷害 18（原本 16）
```

抽牌落在每 2.0-2.4 秒一張，與唐門(2.5s)、劍客(2.1s) 同一個區間。
**集氣確實比原本高**（45 vs 34），符合你要的方向；攻速則比原本慢 3 倍，
這是「保證命中」必須付的代價。

### ⚠ 誠實說明

勝率這個數字我的機器人測不準 —— 同一組設定重跑，結果在 53% / 59% / 71% 之間跳，
**±15% 的雜訊**，即使每次都跑到 38 場以上。可靠的是抽牌速率（跨職業 1.99-2.52s，很穩定）。

所以：**節奏我有把握，強度沒有。** 拳師實際玩起來可能還是偏強，
真的要調的話三個常數都在 `game.js` 開頭：`BOXER_ATTACK_CD` / `BOXER_BASIC_CHARGE` / `BOXER_BASIC_DAMAGE`。

## 更新記錄（2026-07-29 第七輪：音效改用物理建模 + 支援真實錄音）

### 先講結論：合成有硬上限，但我上一版離那個上限還很遠

真實的刀劍聲是**錄音**。純合成做不出真正的鋼鐵撞擊，因為那是實體事件的複雜非諧振頻譜。
但上一版的實作也確實粗糙（FM + 濾波噪音），這一版把該用的物理建模補上。

### 改用模態合成

金屬被敲擊時不是發出一個頻率，而是**一整組非諧振的共振模態同時衰減，高頻衰減得比低頻快**。
這才是金屬聽起來像金屬的原因。改用一排高 Q 帶通並聯、以極短噪音脈衝激發來模擬：

- 模態比例取自實體振動模型：自由端細長棒（刀身）是 1 : 2.76 : 5.40 : 8.93 : 13.34 …
- 三組預設：`blade`（刀身）、`trinket`（小金屬件如鏢、釘）、`gong`（厚重金屬，模態密、尾巴長）
- 每次敲擊模態頻率隨機微偏，重複敲不會一模一樣

### 撞擊解剖

照真實事件的結構去疊，而不是挑好聽的波形：

```
撞擊 = 瞬態(1-3ms 寬頻喀) → 衝擊體(頻譜在數十毫秒內快速下塌) → 共振尾(模態衰減)
爆炸 = 爆裂 → 下掃氣爆 → 次低頻衝擊 → 碎片散落 → 長尾轟鳴
破空 = 帶通頻率與音量同時先升後降
```

新增的合成單元：`crack`（接觸瞬態）、`body`（頻譜下塌的衝擊體）、`thump`（帶飽和的次低頻）、
`whoosh`（破空）、`debris`（碎片）、`modal`（模態）、`saturator`（非線性飽和）。
噪音也分白／粉／棕三種色彩 —— 白噪音聽起來就是「嘶」很假，悶響與轟鳴改用低頻能量重的棕噪音。

### 用頻譜分析驗證（不是憑感覺）

寫了 FFT 分析，檢查音效是否真的具備該類事件的物理特徵：

| 檢查項目 | 結果 |
|---|---|
| 金屬撞擊的頻譜是否為**非諧振**尖峰（諧振列會像樂器不像金屬） | ✔ 三個金屬音的頻率比都非整數 |
| 高頻是否比低頻**先**衰減 | ✔ 起音頻譜重心 1722Hz → 尾音 1366Hz |
| 爆炸是否有次低頻能量與頻譜下掃 | ✔ 次低頻佔比 90%，重心 2362 → 927Hz |
| 打擊起音是否 < 10ms | ✔ 全部 4.4-9.0ms |

**分析過程抓到三個真問題：**

1. **殘響尾巴太亮。** 初版脈衝響應是等能量白噪音，量測出來尾音的頻譜重心反而比起音**還高**。
   真實空間會吸收高頻，這層假嘶聲是「聽起來像合成器」的主因之一。改用逐漸變重的單極低通產生 IR，
   再於殘響回程加一層低通。修正後頻譜重心正確地往下掉。
2. **模態層根本聽不到。** 校正時量到 blade 在 vol 0.4 時峰值只有 **0.014**，
   而同一個音效裡的衝擊層是 0.6 —— 等於我加的金屬感被蓋掉了 30 倍。
   高 Q 帶通天生輸出就小，補上 `MODAL_GAIN` 之後才真的有金屬味。
3. **勝敗音效只有戰鬥音的 1/10 大聲**（0.065 vs 0.7），打完架根本聽不到。逐一量測後重新配平。

### 真實錄音支援（這才是通往「真的很像」的路）

加了一層覆蓋機制：**在 `sounds/` 放入與音效同名的檔案就會自動改用錄音**，
沒有的繼續用合成，不需要改任何程式碼。支援 `.wav` / `.ogg` / `.mp3`。

- 41 個音效名稱與優先替換建議都寫在 `sounds/README.md`
- 播放時會做 ±4% 微幅變速，連發不會一模一樣
- 用 `file://` 直接開網頁時不會嘗試載入（CORS 會擋），要用本機伺服器
- 測試涵蓋：有音檔用音檔、沒音檔退回合成、fetch 全失敗也不會弄壞遊戲

## 更新記錄（2026-07-29 第六輪：音效全面重做）

原本是「單一振盪器 + 指數衰減」共 8 個音效，所有招式聽起來都像電子錶。全部丟掉重寫。

### 音訊引擎

- **多層合成**：每個音效由四種基本單元疊出來 —— 低頻體感層（`tone`）、濾波噪音層（`noise`）、FM 金屬層（`metal`），加上可設定的起音／衰減包絡
- **程序化殘響**：用衰減噪音自己合成脈衝響應餵給 `ConvolverNode`，不需要外部音檔。每個音效可以個別設定 wet 送出量，演武場因此有石造空間的空間感
- **時間排程用 `AudioContext.currentTime`**，不再用 `setTimeout`（舊版連擊時序會飄）
- **發聲數限流**（上限 40）：百裂崩拳連發、暴雨梨花針針雨這種一次幾十個音源的招式不會把聲音糊掉
- **音高隨機化**：重複的音效每次偏移 ±70 音分，連發不會像卡帶
- **靜音鈕** + `localStorage` 記憶（原本完全沒辦法關聲音）
- **建圖失敗自動降級**：`initAudio()` 包 try/catch，任何節點不支援就永久關閉音訊，遊戲照樣跑

### 各招音色設計原則

| 門派 | 音色方向 | 代表 |
|---|---|---|
| **唐門** | 細、尖、金屬、快 | 千機匣＝11 發細鏢在 0.22 秒內打完的機匣連發；暴雨梨花針＝密度先增後減的一片高頻碎響 |
| **劍客** | 金屬鳴響 + 破空 | 揮劍＝出鞘般的「鏣」；流光劍氣＝拉長的劍芒掃過；斷雲橫砍＝兩刀交叉所以是兩聲，第二聲更重 |
| **拳師** | 低頻肉身撞擊 | 拳頭＝低頻體感＋中頻皮肉＋高頻脆響三層；震山推掌是「推」所以低頻長、沒有脆響；擒龍勁是反向的上升吸音 |
| **魔道** | 暗色轟鳴 | 瞬身斬＝空間撕裂的下墜扭曲；場地攻擊＝地面共鳴；罡氣落地＝悶悶的土石爆開 |

其他細節：暴擊會在命中之上疊一層金屬亮音；玩家受擊時**有護盾與沒護盾是不同的聲音**；拳師普攻揮空也有破空聲（不然會以為按鍵沒反應）；勝敗改成五聲音階的古箏式撥彈與下行加低沉大鑼。

### 驗證（用 `OfflineAudioContext` 真的把聲音渲染出來檢查）

- **41 個音效逐一離線渲染**，檢查峰值、RMS、實際長度、發聲數：全部有聲音、無爆音、長度合理
- **壓力測試五種情境**（平常一擊／技能＋暴擊／大混戰／大招＋針雨＋連發／灌 40 次針雨）
  - 抓到一個真的 bug：「大混戰」情境峰值衝到 **1.162**、削出 7 個樣本。`DynamicsCompressor` 起音再快也擋不住瞬態。加了一級 **tanh 軟削波** 之後上限壓在 0.768，小訊號幾乎不受影響，大訊號變成溫和飽和而不是數位爆音。五種情境全部 0 削波
- 也修掉兩個平衡問題：暴雨梨花針一招吃掉 27/28 個發聲位（任何同時發生的聲音都會被丟掉）→ 減少發聲數並把上限提到 40；敵人普攻是玩家最需要聽到的聲音卻是最小聲的之一 → 音量加大
- **測試自己也抓到一個真問題**：headless 測試的 AudioContext 假實作只有 `createOscillator`／`createGain`，一跑就在 `createDynamicsCompressor` 炸掉 —— 這暴露出 `initAudio()` 原本沒有錯誤處理，**舊瀏覽器少任何一個節點都會讓整個遊戲在第一次按鍵時崩掉**。補上 try/catch 降級，並寫了一個「故意拿掉 `createConvolver`」的測試確認遊戲照樣跑完 90 秒

| 敵人在範圍內 | 整組準心轉金色，敵人頭上標「**中**」，狀態列顯示「可命中」 |

| 按另一張 | 直接改瞄那張，不用先取消 |
| 取消 | `Q`；瞄準中按 `Escape` 也是取消（不會直接暫停） |
| 無目標的卡 | 金絲軟甲／月弧返斬／運氣調息**按一下就生效**，不強迫多按一次（沒東西可瞄，兩段只是白費手續） |

**獨立的瞄準狀態列**：訊息列只有一格，敵人每出一招就會把「再按一次施放」蓋掉（既有的 C6 問題）。所以瞄準提示獨立畫一條，顯示招式名＋可命中／落空＋操作提示，不會被覆蓋。

**每張卡的 `target()`** 盡量沿用 `cast()` 用的同一組 helper（`combatAimCell()`、`boxerControlArea()`、`crossCells()`），能共用的就共用，預覽與實際命中在結構上就不可能不一致。

## 更新記錄（2026-07-29 第四輪：百裂崩拳引導定身）

- 引導 1.6 秒期間**無法移動**（鍵盤與手機滑動兩條輸入路徑都擋）。用 `playerIsChanneling()` 直接從 `effects` 推導，不另外存計時器，不會有走不同步的機會
- 視覺回饋：腳下硃砂鎖定框＋四邊往外的爪＋「定」字，拳師本體加高頻出拳震動 —— 讓「動不了」看起來是招式效果，而不是手感壞掉
- 卡面說明與心法口訣都補上「引導期間無法移動」

**驗證**：引導中連送 97 次方向鍵＋40 次觸控下滑，位置完全沒變；引導結束後立刻恢復可移動。

**⚠ 一個需要你判斷的副作用**：定身期間如果場地攻擊剛好點到你腳下那一格，你是**閃不掉的**。敵人現在有約 31% 的時間在放場地攻擊，所以這不是罕見情況。三種處理方式：

1. 就這樣（引導＝高風險高回報的承諾，多數遊戲的做法）
2. 引導期間給減傷或短暫無敵
3. **按方向鍵可以中斷引導**，代價是拿不到最後那一下重擊（最玩家友善，也是最常見的做法）

我先照你說的只做定身，這三個要哪個跟我說。

**關於血量：** 你說「攻擊頻率太頻繁，血還沒磨完就先死」。降到 400 後一場約 5-11 秒。但這樣 Boss 的整套招式（場地 6.5-9s／招式 5.5-7.5s／瞬身斬 7-11s）又會來不及輪完一次 —— 也就是新寫的梅花樁陣、漫天花雨你可能一場只看到一個。**如果你的實際感受是「挨打太密」而不是「血太厚」，該調的是攻擊密度而不是血量**，對應的常數都集中在檔案開頭：


要的話我可以改成「血量拉回去、但把冷卻全部放寬 30-40%」，那樣招式看得完、挨打也不會那麼密。

**副作用一提：** 劍客普攻從「打準心格」變成「同列飛行」之後命中變容易，但受單發限制，集氣速率實測其實**下降**了（機器人 90 秒抽牌 93 → 53 張）。我沒有動 `charge: 42` 這個數字。

```
requestAnimationFrame(loop)            game.js:2435
```

## 2. 問題清單

分級：🔴 P0 破壞體驗　🟠 P1 明顯影響手感　🟡 P2 打磨

### A. 平衡與機制

#### 🔴 A1. 集氣速率過高 → 手牌永遠是滿的，抽牌完全沒有稀缺性

`game.js:172 / 268 / 409`

| 職業 | 集氣/秒（100% 對位） | 每張卡間隔 | 手牌(4格)填滿時間 |
|---|---|---|---|
| 脈衝使 | 71/s | 1.42s | ~5.7s |
| 劍客 | **150/s** | **0.67s** | **2.7s** |
| 拳師 | 100/s | 1.00s | 4.0s |

`gainCharge()`（`game.js:741`）先 `Math.min(100, ...)` 再進 while 迴圈扣 100，**溢出的氣全部丟掉**。實際結果是：氣條幾乎永遠壓在 100%，玩家不需要做任何取捨，「卡牌」退化成「四個常駐技能鍵」。整個 deck-builder 的核心張力消失了。

#### 🔴 A2. 一場戰鬥只有 6～9 秒

400 次蒙地卡羅模擬（玩家全程追擊對位、抽到就打、不閃避；敵人只算直線彈幕）：

| 職業 | 平均 TTK | 平均剩餘 HP | 平均出牌數 |
|---|---|---|---|
| 脈衝使 | 9.1s | **-7.6（經常戰敗）** | 6.0 |
| 劍客 | **6.0s** | 85 | 8.7 |
| 拳師 | **5.6s** | 119 | 5.4 |

640 HP 的「Boss」撐不到第一次特殊技循環結束。**玩家甚至沒機會看到 orbitBombard / waveSweep / 瞬身斬三種招式各一次**，你寫的最好的 AI 設計玩家看不到。

#### 🔴 A3. `orbitBombard` 有 4 格永久安全區，而玩家出生就站在裡面

`game.js:1155-1160`

路徑 12 格剛好是 4×4 的**外圈**，內圈 `col1/row1`、`col1/row2`、`col2/row1`、`col2/row2` 永遠打不到。
而 `createInitialState()` 把玩家放在 **col 1, row 2**（`game.js:429-430`）— 出生點就是安全格。這招目前是純特效。

#### 🟠 A4. 脈衝使是三職業裡結構性最弱的

它的攻擊條件（同列）**和敵人的攻擊條件（同列）完全相同**。也就是說：脈衝使要輸出，就必須站在敵人的彈道上，1:1 對挨 —— 而它只有 **100 HP**（三職最低）、傷害最低（12）、集氣最慢（24）。這不是「高風險高回報」，是「高風險低回報」。

#### 🟠 A5. 教學文字與實作不符（會直接誤導玩家）

`index.html:68`、`game.js:204` 都寫「劍氣浮空後**接攻擊**可加倍擊飛」，但整份程式碼只有 **斷雲橫砍** 帶 `combo: true`（`game.js:221`）。普攻、追風突刺、月弧返斬接在浮空後 **都不會觸發聯招**。玩家會照著提示按普攻，然後以為機制壞了。

#### 🟡 A6. 卡池深度不足且不對稱

`HAND_SIZE = 4`，而脈衝使／劍客的卡池 **剛好也是 4 張** → 手牌滿的時候必然是「全部卡各一張」，加權抽牌（`game.js:720`）形同虛設。拳師 6 張才勉強有變化。

#### 🟡 A7. 月弧返斬的反擊沒有成本

`damagePlayer()`（`game.js:854`）中，反擊架勢會**完全抵銷任意一次傷害**並反打 46。1.2s 窗口、無冷卻、無次數限制，抽到就是無腦按。

#### 🟡 A8. 沒有勝利獎勵 / 進度 / 關卡

勝利訊息本身就寫了：「模板完成，可以開始加關卡與卡池」（`game.js:830`）。

### B. 打擊感／手感

#### 🔴 B1. 完全沒有 hitstop 與螢幕震動

`update()` 與 `render()` 中沒有任何一處會凍結時間或位移鏡頭。94 傷害的暴擊和 12 傷害的普攻在**物理回饋上一模一樣** — 只有數字大小不同。這是目前最廉價、效果最大的改善點。

#### 🟠 B2. 命中特效只有「擴散圓環」

`burst`（`game.js:1992`）是唯一的通用命中特效：一個線寬 5、半徑 18→60 的圓環淡出。沒有火花粒子、沒有衝擊波變形、沒有受擊白閃。

#### 🟠 B3. 傷害數字沒有 pop、沒有錯位

`game.js` damageNumber 分支：`y = effect.y - progress * 34`，線性上升 + 線性淡出。連續命中（拳師引導每 0.2s 一跳）**全部疊在同一個 x 座標**，變成一團糊掉的數字。

#### 🟠 B4. 斬擊特效是一塊半透明多邊形

`slash` 分支只是 `fillStyle = color + "55"` 然後填格子。劍客的「流光劍氣」在視覺上和拳師的「震山推掌」是同一種東西 —— 沒有刀光弧線、沒有方向感、沒有殘影。

#### 🟡 B5. 沒有攻擊動作，角色是「站著發射特效」

`drawUnit()`（`game.js:1882`）只有 `idle` 呼吸浮動（`game.js:1906`）與 `blink` 無敵閃爍。攻擊時角色本體 **零位移、零 squash/stretch、零預備動作**。

#### 🟡 B6. 浮空是瞬間位移 24px

`game.js:1903`：`lift = airborne > 0 ? 24 : 0`。沒有拋物線、沒有落地，浮空結束瞬間掉回去。

#### 🟡 B7. 音效只有 8 個單振盪器，且無法關閉

`game.js:45 playTone`：單一 oscillator + 指數衰減，無 noise layer、無 filter、無 pitch 隨機化 → 連擊時聽起來像電子錶。沒有靜音按鈕、沒有音量、沒有 BGM。

#### 🟡 B8. 手機操作一次滑動只走一格

`handleBoardPointerUp`（`game.js:905`）：threshold 40px，一次 swipe → `movePlayer` 一格。要走 3 格得滑 3 次。而近戰職業需要欄列雙對位 → 手機上近戰基本無法玩。

### C. 視覺美化

#### 🔴 C1. 高解析螢幕下畫面是模糊的（沒有 DPR 處理）

`index.html:13` 固定 `width="1152" height="648"`，`styles.css:86-92` 用 `width:100%` 拉伸。在 Retina / 2K / 4K 螢幕上 backing store 不足 → **整個畫面（含所有文字）被上採樣糊化**。這是「看起來不專業」的第一元凶。

#### 🟠 C2. 字體依賴系統字，跨平台崩壞

`styles.css:29` 與所有 canvas `ctx.font` 都寫 `Segoe UI, Microsoft JhengHei` — 這是 **Windows 專屬**。在 macOS / Android / Linux 上會 fallback 到完全不同的字重與字寬，canvas 內手算的座標（例如 `game.js:2289` 的 694px 訊息框）會爆版。

#### 🟠 C3. 配色偏灰濁、層次不足

`styles.css:1-16` 的 `--bg #090d11` / `--panel #11171c` / `--line #35434c` 明度差距太小，整體發灰。棋盤兩側 `rgba(22,65,75,.92)` vs `rgba(78,38,44,.92)`（`game.js:1406-1410`）飽和度低，敵我陣營的視覺對立感弱。

#### 🟠 C4. 敵人血條只有 78px，卻有 640 HP

`drawUnit` 呼叫 `drawHpBar(pos.x, pos.y+27, 78, ...)`（`game.js:1945`）。640 HP 壓在 78px 上 → 一次 30 傷害只推動 3.6px，**玩家感受不到自己在推進**。Boss 缺少頂部大血條與分段刻度。

#### 🟡 C5. 背景每幀重畫，卻是完全靜態的

`drawBackground()`（`game.js:1300-1398`）每一幀重算天空漸層、3 層山脈、34 顆星、遠景建築、地面透視線。內容 **完全不變**，卻沒有視差、沒有雲霧流動、沒有光線變化。付了成本卻沒拿到收益。

#### 🟡 C6. 訊息列是單行覆寫的「跑馬燈」

`state.message` / `game.message` 在 **28 處**被直接覆寫，`drawWrappedText` 最多 2 行（`game.js:2304`）。重要訊息（瞬身斬預警）會被瑣碎訊息（「劍客普攻揮空」）瞬間蓋掉。沒有優先級、沒有停留時間、沒有堆疊。

#### 🟡 C7. HUD 沒有卡牌與氣條的視覺關聯

氣條（`index.html:27-35`）和手牌（`index.html:57`）在版面上是分開的兩塊，玩家看不出「氣條滿了會變成一張卡進到某個格子」。

### D. 程式架構與效能

#### 🔴 D1. 2489 行單檔，無模組邊界

卡池資料、AI、物理、渲染、DOM 綁定全部混在同一個作用域，並且**共用一個全域 `state`**。卡牌的 `cast(game)` 收了 `game` 參數，但內部同時直接呼叫操作全域 `state` 的函式（如 `addProjectile`、`applyEnemyDamage`）— 參數其實是假的解耦。要加第二個敵人或第二關會立刻卡死。

#### 🟠 D2. `drawGrid` 每幀建立 32 個漸層物件

`game.js:1403`：`createLinearGradient` 在 4×4×2 的雙層迴圈內。加上 `drawBackground` 的 shadowBlur（全檔 16 處）與每幀山脈重繪 → 低階裝置掉幀的主要來源。

#### 🟠 D3. `renderHand()` 每次抽卡都重建整個 DOM 並用 innerHTML

`game.js:2375` `handEl.innerHTML = ""` + `game.js:2392` 用模板字串塞 `card.name` / `card.description`。目前資料是硬編碼所以安全，但一旦卡牌名稱來自使用者輸入或存檔就是 XSS 洞。也讓「卡牌抽出／消失」無法做過場動畫（DOM 被整批換掉）。

#### 🟡 D4. 死碼與空殼

- `addRowPulse()`（`game.js:565`）定義後 **從未被呼叫**，但 `drawEffects` 還為它保留分支。
- `swordsmanAimCell()`（`game.js:541`）只是 `combatAimCell()` 的別名。
- `drawSwordsmanAim()`（`game.js:1472`）名字說劍客，實際判斷 `["swordsman","boxer"]` — 命名誤導。

#### 🟡 D5. 沒有 lint / test / 型別

2489 行純 JS，卡牌數值散落在 14 個 `cast()` 內。改一個數字沒有任何自動驗證。

### E. UX / 無障礙

- 🟠 **切換職業直接重開對局**（`game.js:2477-2482`），無確認 → 打到一半誤點就沒了。
- 🟡 `aria-live="polite"` 掛在整個手牌容器（`index.html:57`），每次抽卡讀屏器會念完 4 張卡的完整描述。應改掛在專用的訊息區。
- 🟡 **沒有存檔**：職業選擇、最佳時間、音量都不記憶。
- 🟡 **鍵位不可改**，且左手位（WASD+J）與方向鍵位（→+Space）混用，1-4 是唯一的技能鍵。
- 🟡 canvas 內所有文字對讀屏器完全不可見，戰況只能靠視覺。

## 附錄 A：模擬方法

第 2 節的 TTK 數字來自 400 次／職業的蒙地卡羅模擬，模型假設：

- 玩家以 0.13s/格 的移動 CD 全程追擊對位，對位就攻擊，手上有卡就立刻施放
- 敵人依原始碼機率隨機走位（0.62～1.07s）、彈幕（1.05～1.60s、16 dmg、同列才命中）
- 暴擊 15%×2 倍、傷害浮動 ±10%，皆與 `rollDamage()`（`game.js:816`）一致
- **保守處**：未計入敵人特殊技與瞬身斬傷害（會讓玩家更難）
- **樂觀處**：未計入玩家閃避與走位失誤（會讓玩家更強）

兩者大致抵銷，TTK 6～9s 的量級結論穩健。建議把此腳本收進 `tools/balance-sim.js`，每次改數值都重跑。
